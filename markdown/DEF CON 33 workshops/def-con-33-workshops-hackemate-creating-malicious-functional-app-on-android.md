## Slide 22

Workshop

###### **Analysis**

**1. Generating the Malicious Payload: msfvenom was used to create a payload with Android Meterpreter Reverse TCP, allowing the attacker to gain control when the victim executes the infected application.**

**2. Extracting and Modifying a Legitimate Application: APKTool was used to decompile an official application, with the goal of injecting malicious code within its original structure while maintaining its legitimate appearance and functionality.**

**3. Injecting the Malicious Code: The Metasploit code was inserted within the Smali (.smali) files, enabling the application to execute the payload without altering its expected behavior.**

**4. Repackaging and Signing: After injection, the application was repackaged and digitally signed to bypass Android’s installation restrictions.**

**5. Establishing Remote Access: Metasploit Multi/Handler was set up to listen for incoming connections from infected devices, allowing the attacker to remotely execute commands using Meterpreter.**

## Slide 26

Workshop

###### **Co n** **c l** **us i** **o n** **s**

###### **1. Exploiting Trust & Reverse Engineering Risks**

Attackers modify legitimate apps using APKTool and smali, embedding malicious code while keeping the app’s interface unchanged, making detection difficult.

###### **2. Evasion & Persistence Techniques**

Repackaging and signing the app bypass Android security. If combined with obfuscation, it becomes harder for antivirus to detect.

###### **3. Full Device Compromise via Meterpreter**

The attack grants remote access, enabling data theft, camera/mic activation, and keylogging, posing a severe security risk.

###### **4. Mitigation & Defense Strategies**

Users should verify app integrity, enforce Google Play Protect, restrict unknown app installations, and implement Mobile Threat Defense (MTD) to prevent infections.
