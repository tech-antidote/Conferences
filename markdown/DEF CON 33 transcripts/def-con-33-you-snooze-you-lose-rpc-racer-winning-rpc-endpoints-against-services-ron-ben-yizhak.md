We're going to talk a lot today about the RPC protocol. So let's first understand what it is.

The remote procedure call is used for inter process communication between clients and servers. The server exposes functionalities, certain actions and logics. And the client can request the server to execute them on its behalf. The server can run on the same machine as the client or on another computer on the network. Both RPC clients and servers use an interface definition language file or IDL file. It contains the properties of the RPC interface like definitions of structs, functions and most importantly the UUID. This unique identifier is used by the server when it registers to the machine and used by the client when it looks for its server. Before a client can communicate with a server, it first needs to create a binding handle. It is composed of three parts. The first part is the protocol sequence. This determines which protocol will encapsulate the RPC communication. The three most common protocols are TCP, named pipes over SMB and the advanced local procedure call or LPC for short.

This protocol is used to transfer messages efficiently and securely between processes running on the same machine only. The second component is the network address which can be an IP address or computer name. And the last part is the end point. The meaning of it is different for every protocol sequence. For TCP it is the port number.
