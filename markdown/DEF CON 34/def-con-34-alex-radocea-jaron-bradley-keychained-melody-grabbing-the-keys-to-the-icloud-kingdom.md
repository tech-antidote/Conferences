## Slide 6

- Let’s suppose that we go and we buy ourselves a brand new Apple computer.

- You are simply logging into the icloud with a username and password. However, in the background, your device is creating what Apple calls a “circle of trust”.

- This is a well thought out process for allowing end to end encryption of many categories of your iCloud data. The idea here is that the secrets in the iCloud keychain and other services should always be encrypted and should only be readable to the devices inside of this trusted circle.

- Taking this a step further. Apple has made it so that these secrets are only in memory and can not be pulled off the disk.

## Slide 7

- Understanding the secure enclave

   - Separate Coprocessor from the Application Processor

   - It runs it’s own operating system called sepOS

   - Has a hardware cryptographic UID Key fused into it. Not visible to the user in any way, not directly readable by sepOS or iOS.

   - Used to generate secrets. Using this unique per-device key

- This processor is working with macOS to ensure all of your credential secrets, remain secrets while at rest.

- Creating a new iCloud account and logging into it from a new device establishes your new circle of trust

- A private public keypair is generated by your system using randomness from the secure enclave

- Keep in mind that the private key is never shared with Apple or backed up in plaintext with iCloud.

- Public key is added to the circle of trust and represents the new computer’s identity in the circle.

- Private key is used to sign the circle which is used later to ensure it can’t be tampered as that would break the signature

- Even Apple can not add entities to the circle of trust without an existing trusted device key pair.

- iPhone generates a private/public key pair

- The original device that is already a part of the “circle” is used to approve the addition of that new device.

## Slide 12

- The original concept of a trusted circle used to be much simpler (off the record protocol)

- Over time Apple has switched to a complex trust graph model that is referred to as Octagon

- In Octagon, we have zones for various types of services that Apple offers. (Fuller list of zones shown later in demos)

• Top level keys

- TLKs are an AES key per zone

- TLKs are synchronized keys. Shared between devices

- TLK sharing based on policy, not all devices access all zones

- TLK AES key unwraps A/C keys -> decrypt per-record keys in each zone, record keys decrypt CloudKit record data

- TLK -> Class A/C keys -> Item keys -> Items

- Policy decides what device gets which tlkShares (For example: MacBook does not need Health secrets)

## Slide 14

- The vulnerability lies in the details of how the various peer’s are managed locally on a macOS system.

- Trusted Peers Helper is an XPC service that plays an important role in ensuring that your macBook stays aware of all the other trusted devices in your iCloud.

## Slide 15

# The process

- Looks up the new Mac's Octagon public encryption key — from TrustedPeersHelper.db (owned by user on macOS. Root not required)

- Fetches the TLKs from keychain-2.db (AKS decrypts them into memory)

- Encrypts each TLK to the new Mac's public key — producing TLKShares

- Uploads those TLKShares to iCloud

- Writes the new Mac as a peer record into its own TrustedPeersHelper.db

# Upon logging new device into the iCloud

1. Using secure random bytes and a salt from your AppleID, new entropy used to derive three items …

   1. Escrowed signing key

   2. Escrow Encryption Key

   3. Escrow Symmetric key

## Slide 30

Visibility and Remediation

- Visibility

   - otctl status --json

   - ckksctl status

- Fix

   - Apple fixed the inject logic bug to address the cloud security dumping vulnerability

   - Escrow no longer leaks into UID-wrapped backups

- Reset of encryption (proceed with caution)

   - ckksctl cloudkit-reset

- otctl - can be used to learn more about trusted devices that your computer knows about

- ckksctl - can be used to see the TLKShares

- Reseting iCloud encryption can be done with the undocumented ckksctl cloudkit-reset command, however, this is not officially supported by Apple and could cause data loss. VIP’s who may be compromised should consider researching further.
